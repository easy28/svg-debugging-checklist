Why Is My SVG Blank or Broken?

A symptom → cause → fix checklist for SVG files that render empty, throw errors, come out blurry, or won't open at all — including the eight defects behind almost every broken AI-generated SVG. Every fix below is free, needs no account, and runs entirely in your browser.

1. The SVG renders as a blank rectangle

The file opens without any error, but the canvas is empty. In our experience this comes down to five causes, in order of likelihood:

Everything is fill="none"

The shapes exist and parse, but every one is styled invisible. This one fools people the most because the SVG technically "works". Fix: open it in a browser-based SVG editor, select all, and set a real fill or stroke — or run it through SVG Repair, which detects invisible shapes and makes them visible automatically.

Shapes are drawn outside the viewBox

The markup draws at x="150" while the viewBox says 0 0 24 24 — the artwork is real, it's just off-canvas. Look for suspicious transform="translate(...)" values. Fix: expand the canvas to fit the actual drawing — the repair tool does this for you and reports what it moved.

Missing or invented viewBox

No viewBox, and the browser doesn't know which part of the coordinate system to show. Fix: add a viewBox that matches the coordinate range you actually draw in.

NaN or Infinity coordinates

d="M 10 10 L NaN 50" is syntactically present and renders as nothing. This shows up constantly in generated and hand-converted files. Fix: run the repair pass, which zeroes out non-numeric coordinates and tells you where they were.

CSS classes that don't exist in the file

The SVG references class="primary" styling that lived in the page it was exported from. Fix: inline the styles, or restyle in the visual editor where you can see fills and strokes per shape.

Not sure which one you have? Preview the SVG on different backgrounds first — artwork that is white-on-transparent shows up instantly on a black checkerboard.

2. An AI generated it and nothing shows

Language models produce SVG token by token, plausibly — they pattern-match on millions of examples without running an XML validator or a geometry engine. The failure modes are so consistent they can be listed. The eight defects behind almost every broken AI-generated SVG:

  • Missing xmlns — the #1 killer. Without xmlns="http://www.w3.org/2000/svg" the browser treats the file as generic XML and may refuse to render it standalone or inside an <img> tag.
  • Missing or invented viewBox — see symptom 1.
  • Shapes translated out of view — decorative transform guesswork puts the artwork just outside the frame.
  • A raw & in a label — SVG is strict XML; one unescaped ampersand invalidates the entire document.
  • NaN and Infinity coordinates — models do arithmetic in public.
  • Unclosed or misnested tags — XML parsers are all-or-nothing; one structural slip and nothing renders.
  • Chat prose and code fences — "Sure! Here's your logo:" and ```svg pasted into the file. Browsers don't strip any of it for you.
  • Everything fill="none" — the sneakiest one; the file "works" and shows nothing.

Fix: paste the raw chat output — prose and fences and all — into SVG Repair. It extracts the real markup, repairs the XML, adds the missing attributes, and shows a before/after preview so you can see the fix landed. It also strips <script> tags and event handlers, which AI SVGs occasionally smuggle in and which become a live XSS vector the moment you inline them. 3. The file won't open at all

A parser error, a "could not load" in the browser, or your design tool rejecting the file. Almost always one of:

  • XML syntax errors — unescaped &, a missing quote, an unclosed tag. One error kills the whole document. Fix: the repair pass itemizes every defect it finds and fixes.
  • Wrong file extension — it's actually PNG or JPEG bytes with an .svg name. Fix: trace the raster to a real vector instead.
  • Broken zip-based variant — some tools emit compressed SVGZ. Fix: decompress, then work with plain SVG.

4. The file is huge and slow

Multi-megabyte SVGs usually carry editor metadata, redundant decimal precision, empty groups, and comments. Fixes, cheapest first:

  • Run it through the SVG optimizer — generated and exported files commonly shave 30–60% with no visible loss.
  • If it came from a raster trace, re-trace with fewer colors: PNG to SVG converter.
  • Compress before shipping: how to compress SVG files walks the full stack (optimizer, minify, server compression).

5. Exports to PNG come out blurry

Rasterizing an SVG at its CSS display size gives you a handful of real pixels. You need to export at a multiple of the display size. Fix: export at 2×–4× with the SVG to PNG converter — the full diagnosis is in how to convert SVG to PNG without blur. For a whole icon set at once, the batch SVG to PNG tutorial covers folders of files in one pass — the batch tool handles hundreds of files without uploading them anywhere.

6. Text disappears or renders in the wrong font on other machines

If the SVG references a font that isn't installed, every machine renders it differently — or drops the text entirely. This bites hardest in laser cutting, engraving, and plotting, where the machine follows glyph outlines, not fonts. Fix: convert the text to outlined paths with the Text to Path tool in the editor so the file renders identically everywhere — the reasoning and workflow are in SVG text to path. Then send the outlined file straight to the machine: SVG to G-code or SVG to DXF.

7. You need it in another format and the export is wrong

Pick the destination, not the converter:

  • Images: PNG, WebP, JPEG, PDF, or ICO for favicons.
  • Components: React, React Native, Vue, Svelte, Flutter, SwiftUI, Jetpack Compose.
  • Code: HTML Canvas, Python, PHP, Ruby, C#.
  • Embedding: base64 data URI, URL-encoded, UTF-8 — and the three ways to embed SVG in HTML explains which one to pick and why.
  • Machines: G-code and DXF, after converting text to paths (symptom 6).
